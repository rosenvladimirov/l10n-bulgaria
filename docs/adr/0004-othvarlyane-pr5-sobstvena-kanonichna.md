# ADR-L-0004: Отхвърляне на PR #5 (`hr_leave_balance`) и собствена канонична имплементация

- **Статус:** приет
- **Дата на решението:** 2026-05-13
- **Дата на записа:** 2026-07-13 (консолидация)
- **Взето от:** Росен Владимиров
- **Източник на реконструкцията:** GitHub `l10n-bulgaria` PR #5 (затворен без сливане, OWNER коментар на `rosenvladimirov`); git комит `12b07c8` „[ADD] l10n_bg_hr_holidays 19.0.1.1.0 — hr.leave.balance SQL report (v19 canonical pattern)" (2026-05-13, +93 реда)

> Отхвърлянията са най-ценни (котва §4): показват, че правоносителят е **редактор с преценка**, не пасивен приемник на генериран/предложен код.

## Контекст

Външен принос (PR #5) предложи модел `hr.leave.balance` (SQL view, +43 реда), подаден през GitHub акаунт, с git-авторство на външен контрибутор. Реализацията ползваше легаси `init()` + `CREATE VIEW` подход.

## Разгледани алтернативи

1. **Сливане на PR #5** както е. — **Отхвърлено.**
2. **Собствена канонична имплементация по v19 SQL-report pattern.** — Прието.

## Решение

Росен **затвори PR #5 без сливане** и написа собствена канонична версия — комит `12b07c8` (`hr.leave.balance` SQL report, v19 canonical pattern, +93 реда). Дословно от OWNER коментара: „Going with a v19-canonical implementation directly in `l10n_bg_hr_holidays` 19.0.1.1.0 (commit 12b07c8) rather than merging this PR. Same goal, same SQL semantics — but built using the canonical Odoo 19 SQL-report pattern instead of the legacy `init()` + `CREATE VIEW` approach. … Closing this PR."

## Обосновка

Каноничният Odoo 19 SQL-report pattern е предпочетен пред легаси `init()`+`CREATE VIEW` — техническа/редакторска преценка за качество и съответствие с версията. Целта и SQL семантиката са същите; имплементацията е преработена от нулата под авторството на Росен.

## Последици

- Шипнатата версия на `hr_leave_balance` е на Росен (`12b07c8`), не предложената в PR #5.
- Пример за редакторски контрол: предложен изход е отхвърлен и заменен със собствен.

## Произход на приноса (задължително, честно)

- Решението е взето от: **Росен** — изрично, с публичен OWNER коментар.
- Имплементацията е: **собствена (Росен), с AI асистенция**; каноничната версия е негов комит.
- Забележки: този ADR документира **факт за решение** (кой какво отхвърли/написа), не правна квалификация на приноса — тя е в отделния доказателствен извлек и е работа на адв. Костов.
